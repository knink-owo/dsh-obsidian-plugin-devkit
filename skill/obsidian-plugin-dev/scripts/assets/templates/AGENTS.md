# AGENTS.md

This repository is an Obsidian community plugin. Read this file before changing code.

## Commands

- `{{PACKAGE_MANAGER}} install` — install dependencies.
- `{{PACKAGE_MANAGER}} run dev` — esbuild watch build; writes `main.js` on every change.
- `{{PACKAGE_MANAGER}} run build` — type-check and production bundle. Must pass before committing.
- `{{PACKAGE_MANAGER}} run lint` — ESLint with the `obsidianmd` recommended rules.

A build passing is not evidence that the plugin works. UI or behaviour changes have
to be observed in a running Obsidian instance; see "Verification" below.

## Architecture

- `src/main.ts` — plugin entry point. The default export extends `Plugin`; `onload`
  registers commands, ribbon icons, events and the settings tab.
- `src/settings.ts` — settings interface, `DEFAULT_SETTINGS` and the settings tab.
- `manifest.json` — Obsidian metadata. `id` must equal the install folder name and
  must never change after the first release.
- `versions.json` — map of released version → `minAppVersion`; read by the
  community directory when offering updates.
- `main.js` — generated by esbuild. Never edit or commit it.
- `styles.css` — optional, loaded automatically when the plugin is enabled.

## Hard rules

- The bundle must stay CommonJS (`format: 'cjs'`); Obsidian's loader uses `require`.
- Keep `obsidian`, `electron` and `@codemirror/*` / `@lezer/*` external in esbuild.
- Do not bundle Node/Electron-only APIs into the plugin.
- Only import from `obsidian`; do not reach into Obsidian internals.
- Clean up everything registered in `onload` via the plugin helpers:
  `this.registerEvent`, `this.registerInterval`, `this.registerDomEvent`,
  `this.registerMarkdownPostProcessor`, `this.addCommand`, `this.addRibbonIcon`,
  `this.addSettingTab`. Never leave a raw `setInterval` or unbound DOM listener.
- Respect `minAppVersion`: declarative settings (`getSettingDefinitions`) need
  Obsidian 1.13.0+; legacy `display()` must stay for older minimums. `DeferredView`
  needs 1.7.2+. Pop-out window support needs 1.8.0+.
- Use `requestUrl` from `obsidian` instead of `fetch` (CORS).
- Use `normalizePath` for user-supplied vault paths; prefer `Vault.process()` over
  `cachedRead` + `modify` when editing files.
- Do not use `electron.remote`, `app` internals, or force window focus.

## Submission rules that are easy to violate

- `id`: lowercase letters, digits and hyphens only; no "obsidian"; must not end in "plugin".
- `name`: no "Obsidian", no leading "Obsi", no trailing "dian", no trailing "Plugin".
- `description`: ≤250 characters, ends with `.`, `!` or `?`, no emojis.
- `isDesktopOnly` must be present and accurate.
- GitHub release tag must equal `manifest.json.version`, with `main.js`,
  `manifest.json` and `styles.css` attached.

## Verification before calling work done

1. `{{PACKAGE_MANAGER}} run build` passes.
2. `{{PACKAGE_MANAGER}} run lint` passes.
3. `main.js` exists and is a CommonJS bundle.
4. Version fields agree across `manifest.json`, `package.json`, `versions.json`.
5. UI/behaviour changes were actually observed in Obsidian — reload the plugin,
   open the view/modal/command and look at it.
